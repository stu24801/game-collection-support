四個階段都完成並推上版控。範圍是整個 repo 的四個 Unity 專案， 301 個 C# 檔。這一頁講它是什麼、怎麼驗的、以及之後怎麼被用到。

1最重要的一件事：它抓得到真的 bug

光說「這個工具應該有用」不算數。我把血怒修好之前的程式碼暫時還原後跑檢查：

第一層　只有驗證在讀的私有值　1 個　← 血怒那種形狀
    ** 地城迴響　SkillAtkSpeedMul（驗證讀了 1 次）

剛好只有那一筆、零誤報；換回現在的版本則是 0 個。

該響的時候響、平常安靜——兩邊都要驗。 只驗「現在沒問題」的話，一個永遠回傳「沒問題」的檢查也會通過。

血怒那個 bug 是：攻速倍率宣告了、註解寫得好好的、自動測試也是綠的， 但那個值從來沒被乘進任何計算裡，技能實際完全沒效果，直到你實機回報才發現。 同一輪還有三個同類。測試抓不到是因為它問「屬性回傳多少」——屬性永遠回傳正確的數字。 要問的是「有沒有人讀它」。

3符號消費索引

全 repo 掃到 748 個效果值宣告（倍率、加成、狀態欄位、數值常數），分三層：

層是什麼目前
第一層私有 ＋ 產品零消費點 ＋ 只有驗證讀得到
這是血怒的形狀，會讓出貨前檢查失敗		0
第二層私有 ＋ 完全沒人讀（死碼或還沒接上）0
第三層公開 ＋ 無內部消費點（存取子或設定表，通常不用管）210

分層是這支能不能用的關鍵。第一版直接列「沒人讀的」，吐出 210 筆， 全被兩個早期專案的設定常數淹沒——訊號被雜訊蓋掉，這種東西沒人會看第二次。

判別的關鍵是存取修飾詞：public int Kills => kills; 沒有產品消費點是正常的（本來就是給驗證讀的），而私有的沒有就是有問題。

4手寫的不變條件（八條）

自動產生的地圖回答「什麼連到什麼」，這份回答「連的時候要注意什麼」。 每一條都對應一次真的壞掉的東西，共通特徵是：這些錯誤都不會報錯—— 編譯過、測試綠、畫面正常，但功能沒生效。

條目那次的事故
效果值一定要有消費點血怒等四個技能的加成從來沒被乘進去
狀態 Tick 要排在 early-return 之前擊退在硬直期間整段被跳過；暗影貼身打你時不更新明暗
生成物件要走接好線的入口踩過三次。最明顯：打了 4000 隻怪一本書都沒掉，因為探針生的敵人沒接死亡事件
改了共用狀態就要還原build 31 一盞沒釋放的光把整座地城照亮，摸黑探索失效
驗證要打玩家實際走的入口問屬性回傳值的測試，在技能完全沒效果時仍然是綠的
不要寫沙盒外絕對路徑build 9 每個玩家一進地城就「初始化失敗」，模擬器完全測不出來
自己組的網格要給 UV光環與衝擊波都變成均勻純色的硬邊色塊，看起來像壞掉
對照實驗要同時間同對象沙包擺太近被自己的普攻打到，量出「戰吼中傷害反而變低」

6做的過程中修掉四個會讓它靜靜失效的問題

這些都是跑出來看到不對才發現的，不是預先想到的：

問題後果
跨 Unity 專案的偽陽性CyberAdv 被判成「依賴地城迴響」，只因它自己也有叫 Skills 的東西
型別唯一性用全域判斷原型分支 DnDPaperdoll 類別同名，把 Demo／Enemy／Floor／Gear／Room 全部撞掉——地圖漏掉最常改模組的核心，而且毫無徵兆
樞紐統計只數靜態存取排出來的地城樞紐是 Skills 而不是 Gear／Demo
效能三分鐘掛不進建置流程＝這個檢查不會有人開。優化後 26 秒，並重新拿歷史版本驗過仍然抓得到

7它解決不了的

這是治標。那些問題的根源是 Demo.cs 有 6,078 行、84 個 public 成員 ——地城幾乎所有東西都經過同一個檔案，所以「改一個地方牽動別處」在那裡是常態。 地圖讓「改了沒接上」被抓出來，但不會讓那件事變得不容易發生。

治本是拆 Demo.cs，但那是大工程、風險也高，我不建議現在做。

另外：用正規表示式解析不是編譯器，模組層級的統計可信、單一條邊不要當鐵證； 透過反射或 Inspector 拉的參照看不到。這些都寫在文件的「限制」一節裡。
