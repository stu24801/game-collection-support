1. 後端有沒有記玩家的配置？沒有，而且沒有可借用的欄位

資料表長這樣（server/leaderboard-worker/schema.sql）

CREATE TABLE IF NOT EXISTS scores (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  game       TEXT    NOT NULL,              -- 'vampire' | 'zombie'
  name       TEXT    NOT NULL,
  score      INTEGER NOT NULL,
  time       INTEGER,                       -- 吸血鬼：存活秒數
  kills      INTEGER,                       -- 吸血鬼
  level      INTEGER,                       -- 吸血鬼
  wave       INTEGER,                       -- 殭屍：撐到第幾波
  win        INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);

跟配置有關的欄位：一個都沒有。 沒有職業、沒有武器、沒有被動、沒有精通， 連角色（伯爵／狼人／夜巫／獵人／不朽者）都沒存。

吸血鬼上傳的 body 只有 {name, kills, time, level, win} （VrLeaderboardClient.Submit）。

有沒有可以借用的空欄位？實質上沒有

欄位 吸血鬼有沒有用 能不能借
wave ❌ 沒用（殭屍專用，吸血鬼存 NULL） 不能。Worker 的 vampire 分支根本沒讀 body.wave，而且 listScores 回應也沒有這個欄位——要用它就得改 Worker，那就是禁區
name 有用 上限 12 字，塞了配置就不能顯示名字了
level / kills / time 都有用 —

即使硬要借 wave，Worker 的 LIMITS.wave = 999，只有約 10 個 bit。 剛好夠塞「角色 × 職業 × 主武器」（5 × 5 × 17 = 425 < 999）， 但塞不下完整配裝（17 武器 × 6 級 + 16 被動 × 5 級 + 精通）。

結論

要記錄配置，一定要動 Worker 與 D1 schema：

  1. schema.sql 加一個 build TEXT（或 loadout TEXT）欄位
  2. src/index.ts 的 vampire 分支收下並回傳它
  3. wrangler deploy ＋ 對線上資料庫跑一次 ALTER TABLE

這三件事全部落在 CLAUDE.md 的禁區裡（「不 wrangler deploy、不改 game key」）。 不是做不到，是需要你明確授權，而且要接受線上資料庫遷移的風險。

附帶一提：這個 API 沒有身分驗證（Worker 自己的註解就寫明了 「分數是可以偽造的」）。加了 build 欄位之後，任何人都能 POST 一個 偽造的配置進來，client 端一定要對讀回來的 build 做上限夾制， 不能直接照著生成敵人。

2. 技術上怎麼做「異步」？真正的成本不在網路那一段

「拉別人過去的紀錄、用那組配置生一個 NPC」聽起來像是網路問題， 但網路那一段其實最便宜（一個 GET、一份快取、一個離線退路，半天）。

貴的是這一段：

⚠️ VrWeapons 從頭到尾是綁死玩家的

不是「換一個 owner 參數」就好。每一條開火路徑最後都呼叫傷害敵人的函式：

家族 開火時做的事
Projectile dir.SpawnShot(...) → ShotStep → HitWithKnockback(VrEnemy, ...)
Chain dir.NearestEnemyExcept(...) ＋ dir.DamageArea(...)
Nova / Aura / Arc dir.DamageArea(...) / dir.DamageCone(...)
Zone dir.SpawnZone(...) → ZoneStep → DamageArea
Meteor dir.MeteorStrike(...) → DamageArea

再加上瞄準端：dir.NearestEnemy(pos) 出現在三個地方， dir.Player.PlayAttack() 也直接寫死。

要讓 NPC 真的使用玩家的武器，等於要把「傷害目標端」整個抽象化 （打敵人 vs 打玩家），而那條路徑是全遊戲每一次傷害都會走的 （VrDirector.Hit()）。這是這個功能真正的成本，不是後端。

所以有三種做法，成本差一個量級

做法 忠實度 成本
甲 真的讓 NPC 跑一份 VrWeapons，抽象化傷害目標端 ★★★ 完全忠實 大（動到全遊戲的傷害路徑，而且極容易產生「敵人的落雷打到別的敵人」這種難查的錯誤）
乙 把配置「對映」成既有的魔王能力——BossDef 的 ring／dash／aimed／summon 已經會傷害玩家而且已經驗過 ★★ 讀起來像那個人的風格 中（新增一張對映表 ＋ 一個 BossDef 產生器）
丙 只用名字與強度，不用配置 ★ 只有社交感 小（見第 4 節）

乙是我會選的中間路線：既有的魔王能力系統本來就在傷害玩家， 只要寫一張「配置 → 能力」的對映表：

主武器 落雷／雷霆天罰   → ability "ring"（環爆，已有預警圈）
主武器 飛刀／千刃流星   → ability "aimed"（狙擊彈幕）
主武器 隕石／隕星引力   → ability "aimed" ＋ 半徑放大
職業   暗影行者        → ability "dash"（高速衝刺）
職業   血族領主        → 血量 ×1.4、擊殺回血
被動   複製護符        → 彈幕發數 +1

生出來的是一隻外觀是那個角色、名字是那個玩家、能力反映他的配置的 魔王級敵人。玩家讀到的是「阿明那套雷流很兇」， 而程式上它只是一筆動態產生的 BossDef ——完全走既有的、已經驗過的路徑。

資料流（乙案）

開局（突襲模式）
  └─ 背景 GET /api/vampire/scores?limit=20      ← 已存在的端點
       ├─ 成功 → 隨機挑一筆，存進本機快取
       └─ 失敗／離線 → 用上一次的快取；再沒有就用內建的「名人堂」預設幾筆
  └─ 到 t=4:30 左右
       └─ BuildInvader(entry) → 動態 BossDef → 既有的 SpawnBoss()
            ├─ HUD 走既有的魔王血條，名字換成「阿明的亡魂」
            └─ 被它殺死時，死亡定格已經會顯示「被誰打死」——免費就有

要動到的既有系統：VrDirector（生成入口已存在）、VrBoardClient（已存在）、 VrHud 的魔王血條（已存在）、VrProgress（多一個快取鍵）。 沒有一個是新系統。

美術是 $0：入侵者直接用既有的角色走路素材（那個玩家用哪個角色就用哪套） 再加一層紅色染色與名牌就好。VrEnemy 已經有 baseColor 染色機制， VrWalkArt.Character(id) 也已經在用。不用生任何新素材。

值不值得排進這一版：我建議不要

三個理由：

  1. 這一版已經有五項功能還沒在實機上驗過。 三條進化路線、突擊模式、 無盡模式、新種族職業、新武器組——目前只有靜態檢查（編得過、資料接得起來、 欄位有人讀）過關。再疊一個動到後端的功能，出問題時會很難分辨是誰造成的。
  2. 它動到禁區。 線上資料庫遷移 ＋ wrangler deploy 的風險， 跟「補三條進化路線」不是同一個量級，不該混在同一次出貨裡。
  3. 它的價值可以先用丙案驗證。 如果丙案上線之後玩家根本不在意 「誰來突襲我」，那甲／乙案的投資就是白費的。先用便宜的版本測需求。

4. 更輕量的替代做法（建議這一版做這個）

🥇 排行榜名字幽靈（丙案）— 完全不動後端

關鍵發現：現有的 GET 端點已經回傳足夠的東西了。

GET /api/vampire/scores?limit=N
→ [{ name, kills, time, level, win, date }, ...]

VrBoardClient.Fetch() 已經在用它（看排行榜那個畫面）。有了 name、kills、level、time、win 就能做出：

⚔️ 第 3 名「阿明」的亡魂追上來了 （Lv58・撐過 40 分鐘・通關過）

  • 強度從 level 與 win 推導，不是從真實配置——但玩家看不出差別， 因為他本來就不知道阿明帶了什麼。
  • 外觀用一個既有角色的走路素材＋紅色染色（隨機或依 level 決定）。
  • 名牌掛在頭上，死亡定格已經會顯示「被誰打死」，免費就有一句 「你被『阿明』擊敗了」。
  • 出場時機放在突擊模式的 4:30 左右（第 4 關開頭，玩家已經成型）， 一局一隻，打倒必掉寶箱。

成本：一到兩天，$0 美術，零後端改動，零禁區風險。

🥈 本機幽靈（自己的上一局）— 連網路都不用

把玩家自己最近幾局的成績存在本機（VrProgress 加一個 JSON 鍵）， 突擊模式時拉自己上一局的紀錄來當入侵者：

⚔️ 你昨天那一局的亡魂（Lv46・28,140 分）

賽車遊戲的 ghost 就是這個。好處是離線可用、一定有資料、而且很個人 （「這是我自己」比「這是某個陌生人」更有情緒）。 而且本機是唯一可以存完整配置的地方——VrLoadout 就在手上， 序列化整份配裝完全不用動後端，所以本機幽靈可以直接做甲／乙案的忠實度。

這一點值得特別講：「想要真實配置」與「想要動後端」其實是兩件事。 本機幽靈可以有 100% 真實的配置，代價只是「那個人是你自己」。

🥉 內建名人堂 — 零風險的保底

在資料表裡手寫幾組「名人」配置（像 BOSSES 那樣），隨機挑一個來突襲。 可預期、可調平衡、完全不依賴網路。適合當上面兩個的離線退路， 而不是主要方案。

三個替代方案的比較

資料來源 配置忠實度 社交感 離線 後端 成本
排行榜名字幽靈 線上榜（現有端點） ✗ 推導 ★★★ 用快取 不動 小
本機幽靈 自己的上一局 ★★★ 完整 ✗ ✅ 不動 小
內建名人堂 寫死的資料表 ★★ 手寫 ✗ ✅ 不動 極小
（完整版甲／乙） 線上榜 ＋ build 欄位 ★★★ ★★★ 用快取 要改＋要遷移 中～大

我的建議：這一版做「排行榜名字幽靈 ＋ 本機幽靈」兩個一起。 前者給社交感、後者給配置忠實度，加起來的體感非常接近完整版， 但零後端改動、零禁區風險、$0 美術，而且兩個都是完整版的前置—— 入侵者實體、名牌 UI、出場時機、平衡，全部可以先用它們調好。 之後真的要接線上 build，只是把資料來源換掉而已。

5. 這件事的風險（不論做哪一案都要先想）

風險 說明
名字是使用者自己輸入的、沒有驗證 Worker 的 cleanName 只去控制字元與限長 12，沒有髒話過濾。入侵者的名字會很顯眼地掛在畫面上。要嘛加一層過濾，要嘛只用排名不用名字
API 沒有身分驗證，分數可偽造 Worker 自己的註解就寫明了。如果之後真的存 build，讀回來一定要做上限夾制，不能照著生成
突擊模式目前不上傳線上榜 這是上一輪定的（局長不同、分數基準不一樣）。所以「突擊模式的入侵者」讀的會是標準模式玩家的成績——強度換算要另外想，不能直接拿
離線一定要能玩 這是單機遊戲。抓榜失敗絕對不能卡住開局，要有快取與內建退路
