① 三條缺失的進化路線

十把基礎武器裡有三把沒有終點，其中十字斬是狼人的起手武器。 回頭查了 Expo 原版 data.ts:452——原版也只有 7 組，不是移植漏掉的。

新進化 ＝ 武器 Lv6 × 被動 Lv3 新機制 DPS
🩸 血刃輪舞 ⚔️ 十字斬 🌵 荊棘甲 整圈連斬 ＋ 把敵人整片掃開 82 → 200（×2.43）
☣️ 疫毒領域 🧄 大蒜光環 ☕ 濃縮咖啡 域內敵人受到的所有傷害 +20% 63 → 158（×2.50）
🌌 隕星引力 ☄️ 隕石術 🧲 吸寶磁鐵 落地前先把敵人吸過來 213 → 600（×2.82）

配的三個被動都是目前沒被任何進化用到的。磁鐵原本只有「撿寶石」一個用途， 接上「引力」主題之後，這遊戲第一次有了聚怪手段——原本 AoE 武器只能等敵人自己走進來。

結果：每一把基礎武器現在都有終點了。

順手修掉的真 bug — VrProjectile.cs:93

- knockMul = knockMultiplier <= 0f ? 1f : knockMultiplier;
+ knockMul = knockMultiplier == 0f ? 1f : knockMultiplier;

擊退方向是「敵人 − 玩家」，乘負數就是把敵人拉過來。原本的 <= 0 把負值 當成「沒設定」吃掉。這是階段⑤那把「血鎖」的整個定位。 編譯過、測試綠，症狀只會是「這把武器手感很普通」。

② 10 分鐘突擊模式

為什麼「除以四」是錯的

① 玩家會嚴重欠等級。 敵人強度綁絕對分鐘數，玩家等級綁擊殺數。 時間剩四分之一 = 拿四分之一的裝備打滿強度的敵人。

② 節奏會爛掉。 精英每 12 秒＝精英變雜兵；商人 7 次／10 分鐘＝ 「一期一會」不成立；魔王每 60 秒一隻＝整局都在打王。

實際做的

總時長 / 關卡切點 2400s / 480·960·1440·1920 600s / 120·240·360·480
血量・傷害爬升 1+0.35×分 / 1+0.15×分 1+1.40×分 / 1+0.60×分
終點強度 血 ×15、傷 ×7 血 ×15、傷 ×7（斷言守著）

包圍網 16:00 起每 72s、36 隻 4:00 起每 30s、28 隻

吞吐只 ×2 而不是 ×4，是因為 ×4 會讓最後一段變成每秒 63 隻， 而 MAX_ENEMIES = 1500 在 iPhone 上從來沒實測過（程式註解自己寫明的）。 把峰值再乘四是拿效能去賭。差額用寶石經驗補回來。

⚠️ 那個 2.5 是估的，必須量出來。 玩家的擊殺數在中後期是被自己的清場能力 決定的，不是被刷怪速度——所以「時間 ÷4 就是擊殺 ÷4」這個推論算不出正確倍率。 要用 VR_SHOTS 跑 A/B，在同一個關卡進度上比對兩邊的玩家等級。

實作方式：ModeDef 資料表

VrDirector 有六個地方各自拿 Elapsed 去比對常數（刷怪／精英／包圍網／ 魔王／商人／關卡）。各乘一次倍率的話一定會漏掉一個，而漏掉的那個 不會編譯失敗、也不會讓測試變紅——症狀只是「突擊模式的商人還是照 5 分鐘出現」。 所以旋鈕集中成一張表，加模式變成加資料，不是改流程。

過程中踩到的坑（已修）

MODES 原本宣告在 MERCHANT_TIMES 前面。C# 的靜態欄位照宣告順序初始化， 而 MERCHANT_TIMES 是 static readonly（不是 const）——MODES 建起來的當下 它還是 null，標準模式會在第一次檢查商人時 NullReferenceException。 編譯完全不會抱怨。已移到常數之後，並加了一條斷言守住。

③ 無盡模式

先定義「一輪」

殭屍防線很直接：它本來就是波次制，打完第 8 波 Wave++ 就好。 吸血鬼是連續生存制，沒有波次可以加，所以定義等價單位：

一輪（Cycle）＝ 一次正篇的長度。 輪內的關卡、魔王、商人整組重跑，關卡循環重用既有的五套場地素材 （所以這一項美術成本 $0），機制關（獵殺者、暴風雪）也照樣重來。

節奏感直接沿用——玩家已經熟悉「換場景、每關兩隻魔王」的呼吸。

進入方式：給玩家選，不自動接

撐滿 40 分鐘時跳一個面板：「結算收工」／「♾️ 進入無盡」。

殭屍防線是自動接進去的，吸血鬼刻意不照抄：一局 40 分鐘，玩家很可能就是 想把這場勝利收下來，硬接進無盡等於逼他用「死掉」來結束一場漂亮的通關。

強度怎麼爬

輪 血量倍率 傷害倍率
1（正篇） ×1.0 → ×15.0 ×1.00
2 ×19.5 → ×37.7 ×1.15
3 ×49.0 → ×72.7 ×1.32
4 ×94.5 → ×125.2 ×1.52

底層線性曲線本身可以外插，但線性不夠——玩家的傷害是倍率連乘、 精通還能無限疊，會追過去。所以每輪再乘一個複利（有斷言守著 「新的一輪起點必須高於上一輪終點」，不然進新的一輪反而變簡單）。

魔王血量用線性不是複利（複利會讓第 3 輪的滅世之神變成打不完的血條）， 技能冷卻每輪 ×0.85。

無盡限定機制（新鮮感的來源）

只把數字往上加的無盡，第二次就不會有人打開。 所以做了兩個：

🦹 獵殺者全程在場（第 2 輪起）— 不再只有血月荒原那 8 分鐘。 保留「追 30 休 5」的節奏所以仍有反擊視窗，但每輪 +10 速度（上限 200）： 到第 5 輪你就真的甩不掉了，只能靠減速與擊退。

☠️ 輪迴詛咒 — 每進入新的一輪，三選一必選一張負面效果，換分數 +25%（可累加，七張全拿 ×2.75）：

詛咒 效果 詛咒 效果
🩸 失血 最大生命 −20% 🕰️ 焦躁 攻擊冷卻 +10%
👣 遲滯 敵人移速 +12% 💀 密集 精英改每 30 秒一隻
🧲 短視 拾取範圍 −40% 🚫 貧瘠 寶箱固定 1 件
⚔️ 鈍化 所有傷害 −12%

這讓「打到第幾輪」從耐力問題變成構築問題——玩家會開始盤算 「這輪我扛得住失血還是鈍化」（押了幸運草的人就不能選貧瘠）。

實作上完全複用升級三選一的面板，只是把 Kind 標成 curse、卡片換暗紫色。 詛咒的倍率放進 VrLoadout.Recalc——那裡本來就是把所有倍率連乘的地方。

排行榜：不需要動禁區

我查過 worker（server/leaderboard-worker/src/index.ts:39）：

const LIMITS = { ..., time: 3_600, ... };
time = int(body.time, LIMITS.time, 0);   // > 3600 → 存成 0

無盡一定會撐過 60 分鐘，那些成績的存活時間會全部變成 0。 但排名根本不看時間（ORDER BY score DESC，score = 難度加權擊殺數）——

→ 解法是 client 端 Mathf.Min(Elapsed, 3599)，結算畫面照樣顯示真實時間。 榜上用「win 且 time > 一輪長度」判定並標「無盡」。 沒有 wrangler deploy、沒有改 schema、沒有碰 game key。

又一個「不會報錯」的坑（已修）

AcceptEndless() 原本把 lastCycleSeen 設成 Cycle。這樣 CycleStep 下一幀 會看到「輪數沒變」而什麼都不做——第 2 輪不會重置關卡/魔王/商人，也不會發詛咒， 玩家要撐到第 3 輪（再 40 分鐘）才拿得到第一張。等於整個詛咒系統沒接上， 而且不會有任何錯誤訊息。改成 Cycle - 1。

驗證：三道 gate，每次改完都跑

tools/csccheck/compile.sh — 不用開 Unity 的編譯 gate（約 10 秒）

來源檔 170 個
  正式版：error CS = 0
  VR_SHOTS：error CS = 0

CLAUDE.md 規則 2 要求「建置失敗要 gate」，但開 Unity 重建 Library/ 要十幾分鐘 還吃 1.7 GB。這支直接拿 Unity 內附的 Roslyn 編。兩輪都編—— VR_SHOTS 底下是整套自動驗證流程，平常不編的話改壞了要到真的要跑驗證時才知道。

tools/vrdatacheck/run.sh — 資料層驗證

VampireData.cs 刻意不相依 UnityEngine，可以獨立跑。目前驗 60 幾條，包括：

  • 進化組合完整性、被動 MaxLv ≥ 門檻 3（拿複製護符當鑰匙的話永遠湊不出來）
  • 標準模式的每個欄位等於原本寫死的常數（既有行為不能被改到）
  • 突擊模式的終點強度跟標準對齊（爬升率沒跟著縮放的話這裡會分家）
  • MerchantTimes != null（就是上面那個靜態初始化順序的坑）
  • 輪數換算的邊界（t=2399 / 2400 / 4800 → 差一輪或差一關都會抓到）
  • 無盡強度單調遞增、詛咒完整性、排行榜上限相容性

symbols.py --check — 效果值有沒有消費點

第一層　只有驗證在讀的私有值　0 個
第二層　完全沒人讀的私有值　　0 個

CLAUDE.md 的第一條硬規則。新增的 Pull / Weaken / DamageTakenMul / SpeedMulGlobal / 四個詛咒倍率都有實際消費點。
