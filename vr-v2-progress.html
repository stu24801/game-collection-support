① 補齊三條缺失的進化路線

現況查證

十把基礎武器裡有三把沒有進化終點，而且我回頭查了 Expo 原版 src/vampire/game/data.ts:452——原版也只有 7 組，所以這不是移植漏掉的， 是從來沒設計過。其中十字斬是狼人的起手武器，等於選狼人想追進化 就得先把起手武器換掉。

順手修掉的一個真 bug

VrProjectile.cs:93

// 修改前
knockMul = knockMultiplier <= 0f ? 1f : knockMultiplier;
// 修改後
knockMul = knockMultiplier == 0f ? 1f : knockMultiplier;

擊退的方向向量是「敵人座標 − 玩家座標」，乘上負數就變成「把敵人拉向玩家」。 原本的 <= 0 會把負值一起當成「沒設定」吃掉。

這是提案 ⑤ 那把「血鎖」的整個定位，先修起來放。 這個 bug 編譯過、自動測試也會是綠的，症狀只會是「這把武器手感很普通」 ——正好是 CLAUDE.md 裡記的那一類。

驗證（三道，全過）

我另外寫了兩支可重複跑的檢查，都進了版控：

1. tools/csccheck/compile.sh — 不用開 Unity 的編譯 gate

來源檔 169 個，error CS = 0
✅ 編譯通過

CLAUDE.md 的規則 2 要求「建置失敗要 gate，不能拿舊執行檔跑」，但開 Unity 重建 Library/ 要十幾分鐘、還要吃 1.7 GB 硬碟。這支直接拿 Unity 內附的 Roslyn 去編 Assets/Scripts，約 10 秒。

2. tools/vrdatacheck/run.sh — 資料層驗證

VampireData.cs 本來就刻意不相依 UnityEngine（檔頭註解寫明「可以在 Unity 之外編譯執行、逐欄比對數值」），所以可以獨立跑。驗這些：

  • 每個 combo 的武器／被動／進化 id 都存在
  • 被動的 MaxLv ≥ 門檻 3 ← 這條最重要，拿複製護符（上限 2）當鑰匙的話 那條路線永遠湊不出來，而且完全不會報錯
  • 進化武器標了 Evolved（才不會被三選一直接抽到）
  • 一把武器只對到一條進化、一個進化只被一組指向
  • 家族推導：血刃輪舞 → Arc、疫毒領域 → Aura、隕星引力 → Meteor
  • 既有行為沒被改到：十字斬 Knock == 0、大蒜 Weaken == 0、隕石 Pull == 0
  • 強度落在既有 7 把的區間內

3. symbols.py --check — 效果值有沒有消費點

第一層　只有驗證在讀的私有值　0 個
第二層　完全沒人讀的私有值　　0 個

這是 CLAUDE.md 的第一條硬規則（血怒的病：宣告了、註解寫得好好的、 測試也綠，但從來沒被乘進任何計算）。新增的 Pull / Weaken / DamageTakenMul 都有實際消費點。

共用系統的風險（你要求要講清楚的）

動到什麼 風險 怎麼處理的
VrEnemy 新增狀態欄位 weakenUntil / weakenMul 物件池會重用同一個實例，不清的話上一隻身上的易傷會被下一隻繼承——症狀是「敵人多的時候偶爾有一隻莫名其妙很脆」，而且查不出來 在共用的 ClearAbilities() 重置，跟既有的 slowUntil 同一個位置
VrDirector.Hit() 多乘一個倍率 這是全遊戲每一次傷害都會走的路徑 只加一行乘法，且乘在跳傷害數字之前——跳的數字必須是實際扣掉的血，不然玩家會以為易傷沒生效
FireArc / FireAura / FireMeteor 加分支 可能改到既有武器的行為 三個分支的條件都是「新欄位 > 0」，而既有武器的那三個欄位都是 0，走原本那條。資料層驗證有斷言守住
存檔格式 — 這一階段完全沒動
選單 UI — 這一階段完全沒動（那是階段④的事，也是整個 v2 風險最高的一塊）

還沒驗到的（老實說）

上面三道都是靜態檢查——編得過、資料接得起來、欄位有人讀。 「易傷有沒有真的讓傷害變高」「引力有沒有真的把怪拉過去」這種行為層的事， 要開 Unity 跑 VR_SHOTS 才驗得到。
